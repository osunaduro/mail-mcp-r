# 6. Archivo de Configuración

## 6.1 Objetivo

El archivo de configuración constituye la única fuente autorizada para definir las cuentas de correo administradas por el sistema.

Su finalidad es centralizar toda la información necesaria para que la biblioteca pueda establecer comunicación con los distintos servidores de correo sin requerir configuración adicional por parte de las aplicaciones consumidoras.

Toda cuenta administrada por el sistema deberá estar previamente definida en este archivo.

---

## 6.2 Principio de Configuración Centralizada

Toda la configuración relacionada con las cuentas de correo deberá mantenerse en un único archivo administrado exclusivamente por el administrador del sistema.

La biblioteca cargará este archivo durante su inicialización y utilizará su contenido para construir el conjunto de cuentas disponibles.

Ningún otro componente podrá modificar esta información durante la ejecución del sistema.

---

## 6.3 Contenido del Archivo

Cada cuenta deberá contener toda la información necesaria para permitir su utilización por la biblioteca.

Como mínimo deberá contemplar:

* Identificador único de la cuenta.
* Nombre descriptivo.
* Tipo de proveedor o mecanismo de comunicación.
* Parámetros de conexión.
* Credenciales necesarias para la autenticación.
* Configuración relacionada con el envío y recepción de correo.
* Parámetros adicionales específicos del proveedor cuando resulten necesarios.

La estructura exacta del archivo podrá evolucionar en futuras versiones manteniendo la compatibilidad con esta especificación.

---

## 6.4 Identificador de la Cuenta

Cada cuenta deberá poseer un identificador único dentro del sistema.

Este identificador será el único dato utilizado por las aplicaciones consumidoras para seleccionar la cuenta sobre la cual desean operar.

El identificador deberá permanecer estable mientras la cuenta exista.

Los consumidores nunca utilizarán direcciones de correo, nombres de servidores ni otros datos técnicos para identificar una cuenta.

---

## 6.5 Carga de la Configuración

La carga del archivo será responsabilidad exclusiva de la biblioteca.

Durante la inicialización deberá:

* Leer el archivo de configuración.
* Validar su estructura.
* Validar la existencia de la información obligatoria.
* Construir el conjunto interno de cuentas disponibles.
* Informar cualquier error que impida el funcionamiento del sistema.

El servidor MCP nunca accederá directamente al archivo.

---

## 6.6 Inmutabilidad Durante la Ejecución

Las cuentas disponibles permanecerán invariables durante la ejecución del sistema.

La creación, eliminación o modificación de cuentas requerirá la actualización del archivo de configuración y el posterior reinicio o recarga del sistema según la estrategia adoptada por la implementación.

Las aplicaciones consumidoras no podrán modificar la configuración mediante la API pública ni mediante herramientas MCP.

---

## 6.7 Protección de Información Sensible

El archivo contendrá información confidencial necesaria para el acceso a las cuentas administradas.

La biblioteca deberá tratar dicha información como datos sensibles.

Las credenciales nunca deberán:

* Formar parte de respuestas públicas.
* Registrarse en archivos de log.
* Incluirse en mensajes de error.
* Exponerse mediante herramientas MCP.
* Ser accesibles para las aplicaciones consumidoras.

La seguridad de esta información constituye una responsabilidad permanente de la biblioteca.

---

## 6.8 Validación

Antes de habilitar una cuenta para su utilización, la biblioteca deberá validar que su configuración sea consistente.

Cuando una cuenta presente errores de configuración, la biblioteca deberá informar el problema de manera clara evitando exponer información sensible.

Una configuración inválida nunca deberá producir comportamientos impredecibles durante la ejecución.

---

## 6.9 Extensibilidad

La estructura del archivo deberá permitir incorporar nuevos mecanismos de autenticación, nuevos proveedores y nuevos parámetros sin afectar las aplicaciones consumidoras.

Toda ampliación futura deberá preservar el principio de configuración centralizada y mantener la compatibilidad con las cuentas existentes siempre que sea técnicamente posible.

---

## 6.10 Principio Rector de la Configuración

La configuración pertenece exclusivamente al administrador del sistema.

Las aplicaciones consumidoras únicamente podrán consultar las cuentas disponibles y operar sobre ellas.

No podrán crear, modificar, eliminar ni alterar la configuración de ninguna cuenta.

Este principio garantiza un entorno controlado, seguro y predecible, evitando que la configuración del sistema pueda ser modificada por aplicaciones o asistentes que utilicen la biblioteca o el servidor MCP.
