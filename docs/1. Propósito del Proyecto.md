# 1. Propósito del Proyecto

## 1.1 Objetivo

El objetivo de este proyecto es desarrollar una biblioteca de software destinada a unificar el acceso y la administración de múltiples cuentas de correo electrónico mediante una única interfaz de programación estable, independiente del protocolo y del proveedor de correo utilizado.

La biblioteca deberá abstraer completamente los mecanismos de comunicación con los distintos servicios de correo, permitiendo que cualquier consumidor interactúe con las cuentas configuradas mediante operaciones de alto nivel, sin necesidad de conocer detalles técnicos sobre IMAP, SMTP, Exchange, Microsoft Graph u otros protocolos o tecnologías que puedan incorporarse en el futuro.

Como complemento de la biblioteca, se desarrollará un servidor MCP (Model Context Protocol) cuya única responsabilidad será exponer las capacidades de la biblioteca como herramientas consumibles por asistentes de inteligencia artificial u otros clientes compatibles con dicho protocolo.

Desde el punto de vista arquitectónico, la biblioteca constituye el componente principal del proyecto, mientras que el servidor MCP representa únicamente una capa de exposición de funcionalidades.

---

## 1.2 Problema que resuelve

Actualmente, las aplicaciones que necesitan interactuar con cuentas de correo electrónico suelen implementar directamente la lógica de comunicación con cada proveedor o protocolo, generando un fuerte acoplamiento entre la aplicación y la tecnología utilizada para acceder al correo.

Este proyecto busca eliminar dicho acoplamiento mediante una capa de abstracción que represente el dominio del correo electrónico utilizando entidades y operaciones propias, independientes de cualquier implementación particular.

Como resultado, las aplicaciones consumidoras podrán trabajar siempre de la misma manera, independientemente del tipo de servidor o proveedor utilizado por cada cuenta configurada.

---

## 1.3 Objetivos de Diseño

El proyecto deberá cumplir los siguientes objetivos fundamentales:

* Proporcionar una API única, consistente y estable para todas las operaciones relacionadas con correo electrónico.
* Ocultar completamente los detalles de implementación de cada proveedor de correo.
* Permitir la incorporación de nuevos proveedores sin modificar la interfaz pública de la biblioteca.
* Mantener una separación estricta entre la lógica de negocio y los mecanismos de exposición mediante MCP.
* Facilitar la reutilización de la biblioteca por aplicaciones distintas al servidor MCP.
* Centralizar toda la configuración de cuentas en un único archivo administrado por el sistema.
* Garantizar que únicamente puedan utilizarse cuentas previamente configuradas por el administrador del sistema.

---

## 1.4 Alcance de la Primera Versión

La primera versión del proyecto estará orientada exclusivamente a las operaciones fundamentales de administración de correo electrónico.

Como mínimo deberá permitir:

* Listar las cuentas disponibles.
* Listar las carpetas de una cuenta.
* Listar mensajes.
* Leer mensajes.
* Enviar mensajes.
* Responder mensajes.
* Reenviar mensajes.
* Mover mensajes entre carpetas.
* Eliminar mensajes.
* Marcar mensajes como leídos o no leídos.
* Gestionar adjuntos básicos (listar y descargar).

Quedan expresamente fuera del alcance de la primera versión funcionalidades como calendarios, contactos, reglas automáticas, sincronización avanzada, búsquedas complejas, administración de usuarios y cualquier otra característica que no resulte imprescindible para la gestión básica del correo electrónico.

---

## 1.5 Filosofía del Proyecto

Este proyecto adopta como principio fundamental que toda complejidad relacionada con el acceso al correo electrónico debe permanecer encapsulada dentro de la biblioteca.

Las aplicaciones consumidoras nunca deberán conocer el protocolo utilizado, el proveedor del servicio, los mecanismos de autenticación ni los formatos internos empleados para representar los mensajes.

La biblioteca ofrecerá una representación uniforme del dominio del correo electrónico y será la única responsable de traducir dicha representación hacia las tecnologías específicas utilizadas por cada servidor de correo.

El servidor MCP no implementará lógica de negocio. Su función será exclusivamente actuar como intermediario entre los clientes MCP y la biblioteca, exponiendo las operaciones disponibles sin alterar su comportamiento ni incorporar reglas adicionales.

Esta separación garantiza un diseño desacoplado, reutilizable, extensible y preparado para integrarse en sistemas de mayor complejidad en el futuro.
