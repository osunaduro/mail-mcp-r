# 5. Servidor MCP

## 5.1 Objetivo

El servidor MCP constituye la capa de integración entre la biblioteca de correo y los clientes compatibles con el protocolo Model Context Protocol (MCP).

Su única finalidad es publicar las capacidades ofrecidas por la biblioteca como herramientas accesibles para asistentes de inteligencia artificial u otras aplicaciones compatibles con dicho protocolo.

El servidor MCP no constituye el núcleo funcional del proyecto ni implementa lógica de negocio propia.

---

## 5.2 Responsabilidad Principal

La responsabilidad exclusiva del servidor MCP será actuar como intermediario entre los clientes MCP y la biblioteca.

Para cada solicitud recibida deberá:

* Recibir la invocación de una herramienta.
* Validar los parámetros de entrada.
* Invocar la operación correspondiente de la biblioteca.
* Obtener el resultado.
* Transformarlo al formato esperado por MCP cuando resulte necesario.
* Devolver la respuesta al cliente.

No deberá realizar ninguna otra tarea funcional.

---

## 5.3 Responsabilidades Excluidas

El servidor MCP no deberá:

* Implementar lógica de negocio.
* Comunicarse directamente con servidores de correo.
* Administrar conexiones IMAP, SMTP, Exchange o cualquier otro protocolo.
* Interpretar reglas relacionadas con mensajes.
* Mantener información propia sobre las cuentas configuradas.
* Modificar el comportamiento de la biblioteca.
* Acceder directamente al archivo de configuración.

Toda funcionalidad relacionada con el correo electrónico deberá delegarse exclusivamente en la biblioteca.

---

## 5.4 Herramientas Expuestas

El servidor MCP deberá exponer únicamente operaciones funcionales pertenecientes al dominio del correo electrónico.

Entre ellas podrán incluirse:

### Gestión de cuentas

* Listar cuentas disponibles.
* Consultar información de una cuenta.

### Gestión de carpetas

* Listar carpetas.
* Crear carpetas.
* Renombrar carpetas.
* Eliminar carpetas.

### Gestión de mensajes

* Listar mensajes.
* Leer mensajes.
* Buscar mensajes.
* Mover mensajes.
* Copiar mensajes.
* Eliminar mensajes.
* Marcar mensajes.
* Obtener información detallada de un mensaje.

### Envío

* Enviar mensajes.
* Responder mensajes.
* Reenviar mensajes.
* Guardar borradores.

### Adjuntos

* Listar adjuntos.
* Descargar adjuntos.

Todas las herramientas deberán corresponder directamente con operaciones existentes en la biblioteca.

---

## 5.5 Herramientas Prohibidas

El servidor MCP no deberá exponer herramientas destinadas a modificar la configuración interna del sistema.

Quedan expresamente prohibidas herramientas que permitan:

* Crear cuentas de correo.
* Eliminar cuentas configuradas.
* Modificar credenciales.
* Cambiar servidores.
* Alterar parámetros internos de conexión.
* Cambiar el comportamiento de la biblioteca.
* Administrar proveedores de correo.

La administración del sistema será una tarea exclusiva del administrador y nunca de los consumidores del servidor MCP.

---

## 5.6 Gestión de Cuentas

El servidor MCP no conocerá cómo se encuentra implementada una cuenta.

Cuando un cliente solicite operar sobre una cuenta determinada, simplemente enviará dicho identificador a la biblioteca.

Será responsabilidad exclusiva de la biblioteca:

* Verificar que la cuenta exista.
* Determinar el proveedor correspondiente.
* Seleccionar el mecanismo de comunicación adecuado.
* Ejecutar la operación solicitada.

El servidor MCP permanecerá completamente ajeno a dichas decisiones.

---

## 5.7 Independencia de la Biblioteca

El servidor MCP dependerá únicamente de la interfaz pública de la biblioteca.

No accederá a clases internas, estructuras privadas ni componentes de implementación.

Toda comunicación deberá realizarse utilizando exclusivamente el contrato público definido por la biblioteca.

Esta restricción permitirá actualizar o reemplazar la implementación interna de la biblioteca sin modificar el servidor MCP.

---

## 5.8 Manejo de Errores

Cuando la biblioteca informe un error, el servidor MCP deberá limitarse a trasladarlo al cliente de manera consistente.

No deberá intentar reinterpretar, corregir o modificar el comportamiento definido por la biblioteca.

La biblioteca continuará siendo la única responsable de generar errores funcionales relacionados con el dominio del correo electrónico.

---

## 5.9 Escalabilidad

El servidor MCP deberá diseñarse como una capa genérica de exposición.

En futuras versiones del proyecto podrán incorporarse nuevas bibliotecas que expongan funcionalidades diferentes (calendario, archivos, usuarios, inventario, tickets, etc.).

Todas ellas podrán convivir dentro del mismo servidor MCP respetando la misma filosofía arquitectónica.

De este modo, el servidor MCP evolucionará como una plataforma de integración mientras cada biblioteca continuará siendo responsable de su propio dominio funcional.

---

## 5.10 Principio Rector del Servidor MCP

El servidor MCP no implementa el negocio.

Toda decisión funcional pertenece exclusivamente a la biblioteca.

El servidor MCP existe únicamente para publicar herramientas compatibles con el protocolo MCP, delegando completamente la ejecución de cada operación en la biblioteca correspondiente.

Cualquier funcionalidad que requiera conocimiento del dominio deberá implementarse en la biblioteca y nunca en el servidor MCP.

Este principio garantiza una arquitectura desacoplada, evita la duplicación de lógica y permite reutilizar la misma biblioteca desde múltiples puntos de acceso sin alterar su comportamiento.
